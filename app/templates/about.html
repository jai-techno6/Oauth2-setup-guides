How it works

The problem this solves

An AI agent that acts in a user's Gmail, Slack or HubSpot needs three things:

  1. A provider OAuth app, registered once by the developer. It holds the client ID and secret, redirect URI and scopes, and it controls the consent screen users see.
  2. An integration in the developer's product (for Composio, an auth config that points at that OAuth app).
  3. User connections: each end user approves the consent screen, and tokens are stored and refreshed.

Layers 2 and 3 work the same way for every provider. Layer 1 varies a lot. GitHub takes a five-minute form. Gmail can take weeks of verification plus a paid security assessment. LinkedIn needs a legal business entity and partner approval. Developers usually find this out by trial and error, after they have planned a launch. These guides tell them up front.

If Composio already manages an OAuth app for a provider, a developer can skip layer 1 while prototyping. They still need their own app to show their brand on the consent screen, request custom scopes, or get their own rate limits. Each guide says which case applies.

What a guide answers

  • Difficulty tier, set by the hardest step needed before external users can connect.
  • Time, split into hands-on effort and waiting on the provider, plus the fastest way to start before approval (testing mode, internal apps, install caps).
  • Requirements, gotchas and blockers, each with a workaround where one exists.
  • Agent vs. you: which steps can be automated, and where a person has to log in, pay, sign terms, upload business documents or record a demo video.
  • Evidence for every claim, plus what is still uncertain.

Evidence labels

tested
Observed by a check that was run: an HTTP probe of discovery documents, endpoints or the developer console, or a live Composio catalog lookup. Each one has a timestamp.
cited
A linked source states it. A ✓ means the quote was found on the cited page. In agent guides, a quote that cannot be found on a readable page is automatically downgraded to inferred.
inferred
Reasoning from cited facts, such as a hands-on estimate based on the number of steps. Treat it as a plan, not a promise.
unknown
Not determined. Listed so you know to ask.

Sources are tagged official (provider domains), Composio, or third-party. Prices and review times that only third-party posts state are marked that way.

The live agent

  1. Research: three web-search passes run in parallel: registration and OAuth basics; review, verification and distribution limits; paid tiers, restrictions and recent changes. Each finding must include a URL and a verbatim quote.
  2. Write: the notes and numbered sources go into a strict JSON schema. The model may only label claims cited, inferred or unknown. Only code-run checks can produce tested.
  3. Probe: without any credentials, the agent fetches OAuth/OpenID discovery documents, checks that the authorization endpoint is live, and opens the developer console. When the console redirects to a login page or blocks bots, that is recorded as the point where a person has to take over.
  4. Composio check (if configured): the live toolkit catalog says whether a managed OAuth app exists.
  5. Verify: the cited pages are fetched and each quote is searched for. Missing source IDs, unsupported citations and quotes that cannot be found all lower the evidence label.

The agent never logs in, creates accounts, solves CAPTCHAs or accepts terms on your behalf.
